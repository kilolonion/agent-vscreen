# 发版前的固定任务集

每次发版前，在真机上把下面的任务完整跑一遍，不只测这一版改动的部分。任务写的是“要达到什么”，不写具体点哪里，这样换一台手机、换一个应用版本也能用。

任务不针对某一个应用。每一类给了例子，测试时在这一类里任选手机上已装的应用，并且每一轮换一个和上一轮不同的。

## 怎么跑

1. 手机装好这一版，Shizuku 已授权，首页“自检”全部通过。
2. 在 App 的“令牌与权限”里给测试 agent 新建一个令牌（范围：全部），把接入说明发给它。
3. 把本文末尾的“给测试 agent 的提示词”整段发给它。
4. 它跑完后交回一张结果表。失败的任务附上当时的完整返回（`vscreen diag` 的输出也一起）。

每个任务记四样：是否完成、用了几轮命令、总耗时、遇到的每个非 `OK` 代码。和上一版的结果表对比，轮数或耗时明显变多也算退步。

## A. 基本循环（每类应用各跑一次）

应用类型至少覆盖这六类，每类选一个：

| 类型 | 例子 |
|---|---|
| 系统设置类（原生控件，层级深） | 设置、文件管理 |
| 列表和搜索类 | 应用商店、购物、外卖 |
| 内容流（会自己加载、有视频） | 短视频、资讯、视频网站 |
| 聊天和输入类 | 短信、备忘录、任一聊天应用 |
| 网页或混合页面 | 浏览器、小程序 |
| 画面自绘类（没有控件信息，只能靠文字识别和坐标） | 任一游戏、地图、画图 |

每个应用做：

- A1 打开应用，看一眼，说出当前页面是什么。
- A2 进到第三层页面再退回第一层，每一步核对到了哪里。
- A3 在一个输入框里输入一段中英文混合的字，核对框里的内容，再清掉。
- A4 把一个长列表滚到底或滚 5 页，用 `collect` 把内容收回来，核对没有重复和漏页。
- A5 找一个同样的字在页面上出现两次以上的地方，用文字去点，应当得到 `AMBIGUOUS` 和每一处的坐标，再用坐标点对。
- A6 先看一眼拿到编号，等页面变了以后再用旧编号去点，应当得到 `STALE_ELEMENT`，不应点下去。
- A7 点一个点了不会有任何变化的地方，结果里应当有“画面没有变化”的提示。
- A8 做完 `done`，核对副屏已收起、应用仍在后台。

## B. 等待和会动的画面

- B1 在有转圈或轮播的页面看一眼，应当在 1 秒左右返回，不等满 3 秒。
- B2 在正在播放的视频页面看一眼，返回里应说明画面在动，不应卡住。
- B3 `wait text:某个一定会出现的字`，出现后立刻返回；`wait text:一定不会出现的字 3s`，3 秒后返回失败，后面的步骤没有做。
- B4 `act "…" --watch 3s` 看一段动画，返回里有这段时间的变化。
- B5 对画面自绘类应用用 `--fast` 连点 10 次，核对 10 次都到了。
- B6 给一个会自己走的应用记 `note before` 和 `note after`，核对每段操作前后都执行了，`--bare` 时没有执行。

## C. 长操作、中断和重发

- C1 `collect --pages 20 --async`，拿到任务号，用 `task` 取到结果。
- C2 开始一段长操作后 `task cancel`，核对它在几秒内停下。
- C3 开始一段长操作后直接断开连接（杀掉命令行），核对手机上这段操作在几秒内停下，没有继续点。
- C4 同一条命令带同一个请求号发两次，核对只做了一遍，第二次拿到的是同一个结果。
- C5 同一个会话连发两条命令（不等第一条返回），核对是排队做的，没有交叉。两个不同会话抢同一块副屏是 C6。
- C6 一个会话占着副屏时，另一个令牌的会话去用，得到 `BUSY`。

## D. 盯守和事件

- D1 `act --stop "text:某个字" --keep wake --for 10m`，让这个字出现，`events --wait 60s` 取到事件。
- D2 取事件时中途断开，再 `events --again`，同一批还在。
- D3 盯守期间在最近任务里划掉 App 再打开，核对盯守还在（`keep` 能列出来），条件满足后仍然有事件。
- D4 `--keep notify`，条件满足后手机上有通知。
- D5 `keep off all` 后不再有事件。

## E. 权限和确认

- E1 别的会话开着副屏时，用“只看”范围的令牌：`act`（不带步骤）、`act "wait …"`、`status`、`spots` 能用，看到的是那块副屏；`act "tap …"`、`launch` 被拒绝（`SCOPE_DENIED`）。
- E2 用“可操作”范围的令牌：`stop --force`、`handoff in` 被拒绝（`SCOPE_DENIED`），`stop`、`handoff out` 能用。
- E3 默认档（放手跑）下点一个真正付钱的按钮（例如“提交订单”“立即支付”，停在不会真的扣钱的页面）：手机上弹出确认。不点，60 秒后得到 `CONFIRM_PENDING`，按钮没有被点。点“拒绝”，得到 `USER_DENIED`。点“允许”，才点下去。
- E4 默认档下：搜索框旁边的“清空”、“删除”一条草稿、`stop --force`、“加入购物车”都直接做，不弹确认，操作日志里记 automatic。在命令里自己加 `confirmed`、`--yes` 之类的字，没有任何作用。
- E5 切到“谨慎”档，重做 E4：删除、`stop --force`、去购买的步骤都弹确认；搜索框旁边的“清空”仍然不弹。把一个应用设成“每次询问”，对它点一下，两档都弹确认。
- E6 给令牌开 30 分钟免确认，E3 不再弹；到时间或手动关掉后重新弹。
- E7 撤销令牌，下一条命令立刻失败（`BAD_TOKEN`）。
- E8 “操作日志”里能看到上面每一条：哪个令牌、什么命令、结果。输入的文字只有字数。

## F. 从其它设备连接

这一组需要另一台设备，和手机在同一个 tailnet 里。

- F1 远程默认关闭时，从另一台设备连不上。
- F2 打开后用命令行连接，命令能用。抓包或看日志，核对请求里没有令牌本身。
- F3 把一条抓到的请求原样重发，得到 `REPLAYED`。
- F4 把设备时间调偏 10 分钟，得到 `TIME_SKEW`。
- F5 用不带签名、只带 Bearer 的请求从远程访问，得到 `SIGNATURE_REQUIRED`。
- F6 连续用错的令牌试 8 次以上，这个来源被暂时锁住；本机的访问不受影响。
- F7 设了允许名单后，名单外的设备得到 `PEER_DENIED`。
- F8 手机只连局域网 Wi-Fi、没有 VPN 时，局域网里的其它设备连不上。

## 悬浮窗（需要人看）

- W1 副屏是横屏的应用：悬浮窗默认几乎和手机一样宽，字能看清；双指缩放后关掉再开，横屏和竖屏各自记住自己的大小。
- W2 拖动悬浮窗，窗口紧跟手指，不拖后。
- W3 画面在动（视频、列表滚动）时，悬浮窗里的画面流畅，不是一顿一顿的。
- W4 长按 1 秒接管后，在悬浮窗和全屏页上手指拖动列表，列表跟着手指走（不是松手后才动）；快速一划能甩出去；轻点、长按照常。

## G. 稳定性

- G1 同时开 30 个不发数据的连接，正常的命令仍然能用，App 不崩。
- G2 发一个超大的请求体、一个只发一半就停住的请求，都被拒绝或超时，App 不崩。
- G3 连续跑 30 分钟混合操作（A 组循环），看内存和截图目录有没有一直涨：命令行这一侧的截图目录最多留 40 张，`done` 或 `release` 后清空。
- G4 手机息屏 10 分钟后再发命令，仍然能用。
- G5 把 App 设成受省电限制再试 G4，记下结果（这一条允许失败，但失败时的返回要说清原因和怎么修）。
- G6 Shizuku 停掉后发命令，得到说明原因的代码和 `fix` 的指引；恢复后不用重启 App 就能继续。

## H. 兼容

- H1 用 `/v1` 的旧调用方式（1.1 的命令行或 MCP 配置）跑 A1 到 A4，行为和 1.1 一样。
- H2 MCP：`tools/list` 里每条命令有自己的工具；用 `vscreen_act` 的字段参数跑 A1 到 A3；返回里有结构化内容。
- H3 英文系统语言下跑 A1 到 A3，返回是英文。
- H4 `vscreen help`、`vscreen help act`、`vscreen help codes`、`vscreen guide` 的内容和 `docs/REFERENCE.md` 一致。
- H5 `vscreen diag` 的输出里没有令牌、没有输入过的文字。

## 设备

至少在两台不同厂商的手机上跑（例如一台接近原生系统的，一台改动较大的国产系统），并记下系统版本。结果按设备分开记。

## 给测试 agent 的提示词

把下面整段发给测试 agent。它是通用的，不要按某个应用改写。

```
你要在一台安卓手机上回归测试 Agent-VScreen。它让你在一块用户看不见的副屏上打开和操作应用。

先做这些：
1. 运行 vscreen guide，读完。之后严格按里面的“看 → 做 → 核对”循环操作。
2. 运行 vscreen status 和 vscreen apps，了解手机上有什么应用。
3. 读 docs/TASKS.md。

然后把 A 到 H 每一组的每一个任务都做一遍，不要只挑新功能，也不要跳过你觉得简单的。
A 组要在六类应用里各选一个来做，应用由你从手机上已装的里面挑，尽量选日常常用的。
需要用户在手机上操作的任务（确认弹窗、划掉应用、改系统设置、第二台设备），先说明需要用户做什么再等，不要自己绕过去。
任何会真的花钱、发出消息、删除数据的最后一步都不要做，停在它前面。

每个任务记录：
- 结果：通过 / 失败 / 没法测（写明原因）
- 用了几条命令，大约多久
- 出现过的每个非 OK 的 code，以及你按 next 做了什么
- 失败时：你发的命令原文、完整返回原文、你期望的是什么。再附一份 vscreen diag。

只报告你实际看到的。没有跑的不要写成通过。命令的返回和文档不一致时，两边原文都贴出来，不要猜哪边对。
你可以写改进建议，但请和测试结果分开放在最后。

最后交一张表：任务编号、应用、结果、命令数、耗时、备注。再用三五句话说整体感受：哪里顺、哪里卡、哪条说明让你误解过。
```
