# Agent-VScreen 和其它手机 agent 的区别

## 一句话定位

Agent-VScreen **不是 agent**，是给 agent 用的**后台副屏**。Mika、DSH Go、Minis 这类是完整的 agent 应用（聊天、模型、工具都在里面），手机操作是其中一项功能，只给自己的模型用。Mika 也有后台虚拟屏，但外部 agent 只能通过它的 CLI、Skill 或 MCP 交任务，由 Mika 的模型决定怎么做。Agent-VScreen 不是把虚拟屏单独拆出来，而是围绕副屏搭了一套脚手架（时间感知、本机 OCR、等待和盯守条件、逐步核对、多 agent 协作），让任何 agent 自己直接操作。

## 对比

| | Agent-VScreen 1.1.7 | Mika | Minis 自带的手机操作 | DSH Go 的手机操控 |
|---|---|---|---|---|
| 是什么 | 独立 App，给任何 agent 直接操作 | 完整 agent 应用；外部 agent 通过 CLI/Skill/MCP 交任务给它 | Minis 内置，只给 Minis 用 | DSH Go 内置，只给本机 DSH 引擎用 |
| 在哪块屏上操作 | 后台虚拟副屏，主屏照常用 | 后台虚拟屏，主屏照常用 | 前台主屏（无障碍） | 默认前台主屏；"不打扰模式"可在看不见的屏上操作，要 Android 14+ |
| 需要的权限 | 只要 Shizuku；无障碍可选、只读 | 配对一次无线调试启动内置助手，无障碍由它自动打开 | 无障碍 | 无障碍；不打扰模式另要 Shizuku、Sui、Root 或自连 ADB 之一 |
| 读屏 | 无障碍 + 本机 OCR（ML Kit，可选 PP-OCRv6 small），合并成编号元素 | 无障碍 + 内置文字识别，可选看图模型 | 无障碍 | 屏幕文字，可选看图模型 |
| 时间感知 | 后台每秒约 5 次看屏、约每秒读字并记时间；【这段时间】报告 agent 思考期间的变化并附拼图 | 未见对外提供 | 未见 | 未见 |
| 和 agent 抢 adb | 不占 adb，不改无线调试和端口 | 要开着无线调试（系统关掉后会征得同意再打开） | 不涉及 | 自连 ADB 通道要求一直开着无线调试、连着 Wi-Fi |
| 熄屏 | 只唤醒副屏，不点亮主屏（设计如此，真机待验证） | — | 未查证 | 要保持亮屏解锁，熄屏任务就停 |
| 接入方式 | 命令行 `vscreen`、MCP、HTTP、Operit ToolPkg；可选 Tailscale 让电脑连进来 | Mika 自己的聊天；电脑上的 agent 用 CLI/Skill/MCP 交任务 | Minis 对话里的工具 | DSH 引擎内部工具 |
| 调用模型 | 不调用任何模型，截图交给调用方的模型看 | 用户配置的模型（自带 key 或账号登录） | 用 Minis 当前对话的模型 | 屏幕文字发给所选模型，看图模型会收到截图 |
| 每次返回 | 固定四段：做了什么、这段时间（含 agent 思考期间的画面变化）、现在（编号元素+截图）、注意；每步核对结果，没达到预期就停在那一步 | —（外部拿到的是任务结果） | — | 读屏幕、点按、输入 |
| 用户怎么看、怎么管 | 系统悬浮窗：边框颜色表示状态，按住 1 秒接管，一键停止，原生全屏页，可把应用移到主屏 | 聊天里的实时小窗、后台屏列表、悬浮胶囊；运行中可插话或停止 | 聊天界面 | 悬浮条（胶囊、卡片、小球），暂停、继续、插话、停止 |
| 后台盯守 | `--keep notify/wake`：条件出现时通知用户或叫醒 agent | 定时和条件任务（如每天定时检查，满足条件才通知） | 有 `notify watch` | 未见 |
| 安全保护 | 应用限制（禁止或只读）；付费按钮只做到确认前，返回 `CONFIRM_REQUIRED` | 默认提问模式：花钱前先问；登录、验证码、付款交还用户 | — | 三档确认、应用名单（支付银行默认不碰）、密码验证码和系统设置交还用户、银行卡号身份证号打码 |

Mika 一列只填了它文档里写明的内容，写“—”的是文档里没有提到的。

Minis VScreen（混合版）已冻结在 v0.5.0：命令和 Agent-VScreen 相同，但只能在 Minis 里用，小窗在聊天界面里，`look` 借用对话的模型。今后只更新 Agent-VScreen。

## 我们的优势

1. **不打扰用户**：所有操作都在后台副屏上，用户主屏照常聊天、刷视频，不会被抢走屏幕。
2. **谁都能用**：命令行、MCP、HTTP、Operit ToolPkg 几种接法，Minis、Operit、Termux 里的 agent、DSH、电脑上的 agent 都能接，不绑定某个 agent 或某个模型。
3. **不抢权限**：只用 Shizuku，不占 adb、不动无线调试和 adbd。agent 自己的 adb 照常可用。
4. **报事实，不做判断**：手机侧不调用模型，数据不出手机；画面含义由调用方的模型判断，不会出现"工具替你下了错误结论"。
5. **有时间感**：agent 工作时后台每秒约 5 次看屏、约每秒读一次字并记下时间，【这段时间】覆盖上次返回到现在的画面变化，包括 agent 思考的那几秒，适合倒计时、动画、加载这类会变的画面。配合 `until` 条件、`--stop`、`--watch` 和本轮结束后的 `--keep` 盯守，agent 能等、能盯。
6. **看得清**：无障碍控件树和本机 OCR（ML Kit，可选 PP-OCRv6 small）合并成带编号和坐标的元素，按字符切分可以点一行里的某段字；还有找色块、带刻度放大、边滚边收集整页文字。
7. **结果可核对**：打字会写明落在哪个框、框里现在是什么；等不到的条件会写出实际值；一步没达到预期就停，不盲目往下做。
8. **随时接管**：悬浮窗按住 1 秒接管，停止后只有用户能交还；交还后 agent 必须先看清画面再动。

## 我们的不足

1. **不是完整产品**：要另外有一个 agent 和模型，用户要多装、多配一个 App；Mika、DSH Go、Minis 装一个就能用。
2. **依赖 Shizuku**：手机重启后要重新启动 Shizuku；Android 11 起可用，推荐 14 以上。
3. **安全保护比 DSH Go 弱**：没有分级确认、敏感信息打码和默认"不碰"的支付银行名单，只有用户自己设的应用限制和付费确认拦截。
4. **真机验证少**：主要在一台荣耀 MagicOS 11 上测过；1.1.x 的悬浮窗手势、全屏页、熄屏唤醒还没在真机上验证。
5. **虚拟屏固有的限制**：荣耀 APS 这类系统缩放会让部分横屏游戏在副屏上画面被裁（Shizuku 权限改不了）；带防截屏标记的应用在副屏上可能截不到画面。
6. **厂商后台管理**：荣耀、华为、小米等仍需用户手动允许自启动和后台活动，否则可能被冻结。
7. **冷启动慢几秒**：第一次识别文字要加载约 30 MB 的 OCR 模型。

## 其它同类

- **AutoGLM、豆包手机助手这类**：厂商或大模型公司做的完整助手，靠云手机或系统级权限操作，体验一体化，但不开放给第三方 agent 调用。
- **Droidrun、mobile-use 这类开源框架**：多数从电脑通过 adb 控制手机，在前台主屏操作，需要一台电脑或占用 adb。

Agent-VScreen 的位置是两者之间：在手机本机运行、不要电脑、不占 adb，又不绑定某个 agent。
